# Модуль 3: Структура проекта

**Время**: 1 час
**Цель**: научиться организовывать код в проекте

---

## Почему структура важна

Один файл с кодом — это хорошо для обучения. Но для реального проекта нужно:

- **main.py** — точка входа (запуск программы)
- **utils.py** — вспомогательные функции
- **config.py** — настройки
- **requirements.txt** — список нужных библиотек
- **README.md** — описание проекта
- **venv/** — виртуальное окружение (не трогаем руками)

## Шаг 1: Сквозной проект "Система управления закупками"

С этого момента мы начинаем проект, который будем улучшать в каждом модуле.

**Промпт для Cline:**
```
Создай структуру Python-проекта "supply_manager" (система управления закупками и запасами).
Создай файлы:
1. main.py — точка входа, пока просто выводит "Система управления закупками v1.0"
2. utils.py — пока пустой файл для вспомогательных функций
3. config.py — настройки (пока пустой словарь CONFIG = {})
4. requirements.txt — список зависимостей (пока пустой)
5. README.md — краткое описание проекта
```

## Шаг 2: Виртуальное окружение

**Что это:** изолированная среда с библиотеками для каждого проекта.
Не влияет на другие проекты.

**В CMD (из папки supply_manager):**
```
python -m venv venv
```

Появится папка `venv/`. Её содержимое не трогаем.

**Активация (нужно делать каждый раз при работе над проектом):**
```
venv\Scripts\activate
```

После активации в начале строки CMD появится `(venv)`.

## Шаг 3: requirements.txt

Когда устанавливаешь библиотеки через pip, их список сохраняют в requirements.txt.

Как это будет работать (позже):
```
pip install pandas
pip freeze > requirements.txt
```

Затем другой человек (или ты на новом ПК) делает:
```
pip install -r requirements.txt
```
И все библиотеки устанавливаются одной командой.

## Шаг 4: .gitignore

Некоторые файлы НЕ нужно сохранять в Git:
- `venv/` — виртуальное окружение
- `__pycache__/` — кеш Python
- `.env` — секреты (пароли БД)

**Промпт для Cline:**
```
Создай файл .gitignore для Python-проекта.
Добавь стандартные правила: venv/, __pycache__/, *.pyc, .env, .vscode/
```

## Шаг 5: Связываем всё

Сейчас структура проекта выглядит так:

```
supply_manager/
├── main.py          # точка входа
├── utils.py         # функции
├── config.py        # настройки
├── requirements.txt # зависимости
├── README.md        # описание
├── .gitignore       # игнорируемые файлы
└── venv/            # виртуальное окружение
```

## Как работать с multi-file проектом через Cline

Когда просишь Cline что-то сделать, **указывай имя файла**:

- "В файл `utils.py` добавь функцию, которая..."
- "В файле `main.py` добавь импорт из utils и вызов функции"
- "Создай новый файл `analytics.py` с функцией..."

Так Cline не перепутает файлы.
