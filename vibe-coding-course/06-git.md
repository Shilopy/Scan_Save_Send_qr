# Модуль 6: Git и GitHub

**Время**: 1.5 часа
**Цель**: научиться сохранять версии кода и работать с GitHub

---

## Что такое Git

Git — это **система контроля версий**. Как "сохранить" в Word, но для всего проекта.

**Зачем:**
- Можно откатиться к любой версии кода
- Видно кто и когда что менял
- Можно работать с другими людьми
- GitHub — это "облако" для Git

## Аналогии

| Git | Реальная жизнь |
|-----|---------------|
| `git init` | Создать сейф для документов |
| `git add` | Положить документы на стол для архивации |
| `git commit` | Запечатать конверт с датой |
| `git log` | Посмотреть историю конвертов |
| `git push` | Отправить копию сейфа в облако |
| `git pull` | Забрать изменения из облака |
| `.gitignore` | Список того, что НЕ класть в сейф |

## Шаг 1: Установка Git

1. Перейти на [git-scm.com](https://git-scm.com)
2. Скачать для Windows
3. Установить (все опции по умолчанию)
4. После установки открыть CMD и проверить:
```
git --version
```

## Шаг 2: git init — создаём репозиторий

В CMD из папки `supply_manager`:
```
git init
```
Появится папка `.git` (она скрыта, в проводнике не видна).

## Шаг 3: git add + git commit — первый коммит

Добавляем все файлы в Git:
```
git add .
git commit -m "Первый коммит: структура проекта supply_manager"
```

Поздравляю! Первая версия сохранена.

## Шаг 4: git status — что изменилось

После изменения файлов:
```
git status
```
Покажет какие файлы изменены, какие новые.

## Шаг 5: git diff — что конкретно изменилось

```
git diff
```
Покажет построчно что добавлено (зелёным) и удалено (красным).

## Шаг 6: Рабочий цикл (повторять постоянно)

```
# 1. Проверить статус
git status

# 2. Добавить изменения
git add .

# 3. Закоммитить
git commit -m "Добавил функцию расчета MRP"
```

## Шаг 7: GitHub — облачное хранилище

1. Зайти на [github.com](https://github.com)
2. Зарегистрироваться
3. Нажать зелёную кнопку **New repository**
4. Назвать `supply_manager`
5. **НЕ** ставить галочки (ни README, ни .gitignore)
6. Нажать Create repository

После создания GitHub покажет команды для связи.

**Отправка кода на GitHub:**

Первый раз:
```
git remote add origin https://github.com/твой-логин/supply_manager.git
git branch -M main
git push -u origin main
```

Обычный push (после первого):
```
git push
```

## Шаг 8: Полезные команды Git

| Команда | Что делает |
|---------|-----------|
| `git log --oneline` | Показать историю коммитов (кратко) |
| `git status` | Показать текущее состояние |
| `git diff` | Показать изменения не в коммите |
| `git add .` | Добавить все изменения |
| `git commit -m "сообщение"` | Создать коммит |
| `git push` | Отправить в GitHub |
| `git pull` | Забрать из GitHub |
| `git checkout -b new-feature` | Создать новую ветку |
| `git switch main` | Переключиться на главную ветку |

## Git через Cline

Можно давать Cline Git-команды:

```
Сделай git add . и git commit с сообщением "Добавил модуль прогнозирования"
```

Или:
```
Запушь все изменения в GitHub
```
